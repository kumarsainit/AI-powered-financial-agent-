# AI-Powered Financial Agent

## 1. Overview
Given a user's financial profile, transaction history, recurring income/expenses, payment options, relevant evidence, and a purchase request, the system determines:
- how much is safe to pay
- affordability status
- recommended payment method
- payment plan
- earliest date for full payment
- necessary spending changes
- decision explanation

## 2. Problem
The Buy-or-Wait decision problem requires deciding whether a user should proceed with a requested transaction given their financial realities. For every request, the agent must decide whether the user should pay in full, pay partially, use installments, wait, or not proceed. The agent must account for recurring commitments, pending payments, essential spending, and the minimum balance the user wants to keep, while navigating untrusted evidence and strict rules.

## 3. Approach Overview
Input data
→ canonicalization
→ lifecycle normalization
→ recurrence detection
→ evidence extraction
→ financial-state reconstruction
→ 90-day cash-flow projection
→ affordability calculation
→ payment-plan optimization
→ explanation generation
→ output validation

The core affordability and financial decisions are fully deterministic. Evidence extraction is cleanly separated from the decision logic, ensuring predictable, reliable financial simulation without unpredictable model-based inferences interfering with the math.

## 4. Key Design Decisions
- **Deterministic financial simulation**: Cash flows are explicitly modeled and verified against bounds.
- **90-day safety projection**: Future safety is guaranteed over a strict 90-day rolling window.
- **Minimum balance protection**: The user's minimum required balance is fiercely protected across every projected day.
- **Lifecycle normalization**: Complex payment lifecycles (pending, settled, cancelled, failed) are cleanly collapsed to avoid double-counting.
- **Recurrence handling**: Inferred monthly and weekly cadences extrapolate historical spending conservatively.
- **Evidence/conflict handling**: Conflicting multimodal evidence is resolved using exact challenge precedence rules.
- **Independent gates**: Financial capacity, payment-method eligibility, and user preferences are evaluated independently.
- **Payment-plan optimization**: Safest and cheapest candidate plans are deterministically ranked.
- **Spending-change constraints**: Modifications strictly target flexible recurring expenses, bounded by user permissions.
- **Deterministic output**: Input-order independence is maintained across the entire system.

## 6. Requirements
- Python 3.9+
- pytest

## 7. Setup
Clone the repository and set up a virtual environment:

```bash
git clone https://github.com/kumarsainit/AI-powered-financial-agent-.git
cd AI-powered-financial-agent-
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install pytest
```

## 8. Run Tests
Verify the installation by running the test suite:

```bash
python -m pytest code/tests
```
Expected result: 672 tests passing.

## 9. Generate Output
Generate the final predictions:

```bash
python3 code/main.py
```
This produces `output.csv` in the repository root.

## 10. Output Format
The resulting `output.csv` matches the requested format precisely:
1. `request_id`
2. `amount_safe_to_pay`
3. `affordability_status`
4. `recommended_payment_method`
5. `payment_plan`
6. `earliest_date_for_full_payment`
7. `spending_changes_needed`

The system is strictly deterministic. The order of input rows in the dataset does not change the result, guaranteeing reproducible, byte-identical output across runs.
